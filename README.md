# AIGC Vault Mobile

AIGC Vault 的独立手机网页，用于浏览电脑端同步的图片、视频和提示词，也可以在手机上新建提示词并导出到电脑端。

部署只需要 [index.html](index.html)，不需要在手机上安装浏览器扩展。模型规则已内嵌在 HTML 中，图片、视频和云端数据仍通过相应链接读取。

## 三种浏览方式

本轮验证与截图见[视图交互更新](../docs/mobile-view-refinements.md)。

单击顶部浏览方式按钮，依次切换网格 → 大图 → 纯享 → 网格，选择只保存在手机。切换时保留当前作品、已加载范围和图片位置，不跳回列表顶部；适用于画廊、收藏和搜索。

- **网格**：原有多列缩略图，适合快速找内容。顶部模型标签高度压缩为32px。
- **大图**：单列大图，外框跟随当前预览图的实际比例；显示模型、提示词摘要和详情入口，多图左右滑动时同步调整高度。
- **纯享**：外框按当前预览图片的实际比例自适应，多图左右滑动时同步调整高度；尽量只显示图片，隐藏网页内顶栏、底部导航、作品文字与大部分控件，保留多图张数。右上角“菜单”随时恢复导航，再点“收起菜单”继续纯享；下方“退出”回到进入纯享前的视图，并保留浏览位置。浏览器地址栏和手机系统状态栏由系统控制，页面不保证隐藏。


桌面1.6.8a合集兼容结论与后续适配项见[兼容检查](../docs/mobile-collection-compatibility.md)。

## 能做什么

- **画廊**：查看即梦、MJ、Nano Banana、GPT Image、其他模型的生成内容；图片识别记录有独立入口。
- **搜索和筛选**：搜索模型别名、版本、网站及提示词；按模型系列、版本、网站、媒体、模型信息、画幅和标签筛选。
- **合并采集**：读取电脑同步的合并关系，卡片显示左上角数量标记，详情可切换成员；合并、拆分操作在电脑端完成。
- **详情**：查看多图、切换提示词语言、复制提示词、打开原链接及播放视频。视频失败时保留地址并恢复封面。
- **画板与收藏**：按画板浏览，查看电脑端收藏后同步过来的内容。
- **时间和排序**：默认最新采集，可切换最早采集、最近修改；画廊与搜索支持今天、近7天、近30天，搜索保留最多60条并显示匹配总数。
- **手机新建**：录入提示词、模型系列和版本、语言、图片链接、来源链接、画板及标签；导出 JSON 后可在电脑端导入。
- **屏幕适配**：手机两列、600px 起三列、900px 起四列；支持横屏、触摸滑动和键盘操作。

当前手机端不包含桌面文章库、网页采集器、AI 图片反推服务配置和完整数据库还原入口。

## 部署

### 从仓库构建

在仓库根目录运行：

```bash
npm ci
npm run build:mobile
```

构建会更新手机 HTML 中的共享模型规则，并输出 `dist/aigc-vault-mobile-<手机版版本>.html`。当前输出为 `dist/aigc-vault-mobile-1.1.1a.html`，内容与本目录 `index.html` 一致。

完整扩展的 `build`、`build:firefox`、`zip` 和 `zip:firefox` 也会先生成手机 HTML。共享模型规则来自 [model-mobile-runtime.js](../src/utils/model-mobile-runtime.js)，不要直接修改 HTML 中 `shared-model-runtime` 标记内的生成代码。

### 发布手机网页

1. 将本目录 `index.html` 或构建输出文件部署到 GitHub Pages、COS 静态站点等 HTTPS 地址；若使用构建文件，将它重命名为 `index.html`。
2. 从手机 Safari 打开页面，确认能看到画廊、收藏、画板及设置入口。
3. 在“设置 → 关于”检查“v1.1.1a · 2026-10-30”，确认部署的是本轮文件。
4. 如需主屏快捷方式，从 Safari 的分享菜单选择“添加到主屏幕”。本轮浏览更新沿用已确认的03启动配置；已有主屏图标刷新后检查版本即可。

README、更新日志及测试页不属于运行时必需文件。

## 首次读取云端内容

1. 在电脑扩展中完成采集，并执行上传同步，生成 COS 手机索引 `mobile_meta.json`。
2. 保证该索引可公有读取，索引中使用的图片和视频链接也能被手机访问。
3. 在手机“设置 → 腾讯云 COS 配置”填写完整 Bucket 名称及地域，例如 `my-bucket-1234567890`、`ap-guangzhou`。
4. 点击“同步数据”。成功后即可在画廊、画板和收藏中查看云端内容。

手机只使用 Bucket 和地域读取索引，不需要填写 COS SecretId 或 SecretKey。索引公开读取意味着其中的提示词及媒体链接也可被读取，应按实际内容决定发布范围。

手机“同步数据”是从云端读取并更新本地缓存，不会把手机新建记录直接上传到 COS。电脑端有新内容时，先在电脑端上传，再在手机点击同步。完整协议见 [COS 同步说明](../docs/cos-sync-protocol.md)。

## 浏览、搜索和工作模式

- 画廊右侧可选择“最新采集 / 最早采集 / 最近修改”和“全部时间 / 今天采集 / 近7天 / 近30天”，选择保存在当前手机站点。近7天包含今天与前6个本地自然日，近30天同理。
- 采集排序优先取有效的 `collectTime`，缺失时用 `createdAt`；最近修改优先取 `updatedAt`。时间完全缺失的记录排到最后，相同时间保持稳定顺序。作品生成时间与采集时间不同的记录按采集时间排，刷新和同步不会重写这些时间。
- 搜索覆盖所有可见模型和图片识别记录，沿用所选时间范围与排序，最多展示60条。匹配更多时显示总数，缩小时间范围或增加关键词后再找。详情关闭后保留搜索词、结果和滚动位置。
- 改变分类、时间、排序或筛选会回到列表顶部；看详情再返回保留原位置。画廊和收藏每批追加40条，保留已有卡片。
- 画板内和收藏的记录沿用排序；画板总数与收藏总数不受画廊时间范围影响。筛选标签可单独移除，无结果时可直接清除条件。
- 修改画板隐藏状态后，需在电脑上传同步，再在手机同步。旧索引若只有画板名称、没有隐藏标记，手机无法推断哪些画板应隐藏；应由当前电脑端重新上传索引。隐藏是浏览规则，不会删除云端或原始缓存记录。

本轮范围与回归记录见 [浏览交互更新](../docs/mobile-browse-update.md)。

## 手机新建与导出

点击底部“＋”新建提示词。提示词必填，其余字段按需要填写；图片入口目前接收 HTTP/HTTPS 链接，每行一张，不是手机相册上传控件。

新建内容先存到手机当前站点的本地存储。要回到电脑端：

1. 手机“设置 → 手机端本地记录 → 导出本地记录”。
2. 将下载的 JSON 导入电脑端灵感库。
3. 电脑端再次上传同步，手机再读取云端更新。

导出文件只包含手机新建记录，不包含整份云端库，也不是完整数据库备份。同 ID 的本地与云端记录会合并显示，并保留模型字段、语言及删除状态。

## 本地数据与迁移

| 内容 | 保存位置 |
| --- | --- |
| 手机新建记录 | localStorage：`aigc_mobile_local` |
| Bucket、地域 | localStorage：`aigc_mobile_cos` |
| 手机浏览模式 | localStorage：`aigc_mobile_work_mode` |
| 排序与采集时间范围 | localStorage：`aigc_mobile_browse` |
| 云端原始索引缓存 | IndexedDB：`aigc_mobile_db` / `cache` / `cloud_cache` |
| 云端缓存同步时间 | IndexedDB：`aigc_mobile_db` / `cache` / `cloud_cache_meta` |

每次打开页面时会先显示已有云端缓存，画廊顶部会标出缓存记录数和最近同步时间；旧缓存没有同步时间记录时仍会显示记录数。之后可手动同步云端更新。损坏索引或缓存写入失败不会直接用失败结果替换当前已加载数据。缓存不等于完整离线媒体包，未缓存的图片和视频仍需要联网。

Safari 与主屏应用的存储环境可能不同；看到空库时先核对打开方式和 COS 配置。清除网站数据、迁移域名或更换主屏入口之前，先导出尚未导入电脑的手机新建记录。“清空本地记录”只处理手机新建记录，不删除 COS 数据。

## iPhone 主屏底栏适配

2026-10-27，已通过独立测试页和正式页面的用户实机确认。当前方案为：

- 使用 `apple-mobile-web-app-status-bar-style=black`，即不透明系统状态栏。
- 根文档保持 `100%` 高度，应用容器使用 `100dvh`，保留 `100%` 回退。
- 底栏固定在网页视口底边，保留系统返回的底部安全区；滚动内容另为底栏预留空间。
- 不将 `screen.height` 强行用作网页高度，不写死补偿 59px 或移除 34px 手势区。

实测设备屏幕高 852px，网页高 793px，顶部安全区为 0、底部为 34px；网页从系统顶部状态栏下方开始，底栏可以正常贴到屏幕底部。这个数字组合是本次设备的测量结果，不是所有 iPhone 的固定值。

如果后续复现，先使用 [02 测试页](bar-test.html) 和 [03 不透明状态栏对照页](bar-test-black.html)，分别记录浏览器/主屏模式的截图与“复制诊断数据”，再调整代码。详细过程见 [03 配置交付记录](../docs/mobile-standalone03.md)。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 提示403 | 手机索引的公有读权限，以及 Bucket、地域是否正确 |
| 提示404 | 电脑端是否已上传、目标 Bucket 中是否存在 `mobile_meta.json` |
| 网络请求失败 | 手机网络、目标地址能否访问、控制台是否报告跨域错误 |
| 仍显示旧界面 | 部署的是否为新构建；检查设置页日期，再区分 Safari 与原主屏图标 |
| 手机新建未出现在电脑 | 手机新建需要导出 JSON、电脑导入后再同步 |
| 视频无法播放 | 先打开媒体原链接确认可用性；手机浏览器仍可能受媒体格式及来源访问条件限制 |

## 维护和验证

从仓库根目录执行：

```bash
node scripts/build-mobile.mjs --check
npm test
npm run compile
npm run build
```

手机 UI 浏览器回归脚本为 [review-mobile-ui.mjs](../scripts/review-mobile-ui.mjs)。已安装 Playwright 的环境可运行：

```bash
node scripts/review-mobile-ui.mjs
node scripts/review-mobile-browse.mjs
```

若本项目无法直接解析 Playwright，可用 `MOBILE_REVIEW_PLAYWRIGHT` 指定已有模块的绝对路径。脚本使用隔离模拟数据和模拟 COS，截图及结果默认写入 `output/mobile-ui-review/`；这些结果不能代替全部真实设备与生产同步场景的验收。
